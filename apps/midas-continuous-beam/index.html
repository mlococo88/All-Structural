Civil NX connection

Not checked. Civil NX must be open and show "Connected".

Spans & I-section (web depth varies parabolically)

Web depth D is clear between flanges; total depth = D + ttop + tbot. D varies along each span as a parabola through the left, mid and right values; flange plates are constant within a span. Each element gets a prismatic I-section at the depth of its midpoint (a stepped approximation of the haunch), so more elements give a closer match. Sent to Civil NX as a DB/User "H" section, [H, B1, tw, tf1, B2, tf2, r1, r2] = [total depth, top flange width, web, top flange thickness, bottom flange width, bottom flange thickness, 0, 0], with the element axis at the section centroid. Non-composite steel section only; no deck.

Loads & combinations

DC = γ·A of the I-section (girder only, no deck, haunch or details allowance) is applied as an element uniform load (not as MIDAS self-weight), so MIDAS and the check solver use the same weight. DW is uniform on all spans.

Live load: HL-93 moving load (AASHTO LRFD)

One traffic lane along the girder line (eccentricity 0). Vehicles: HL-93 design truck (8, 32, 32 kips; 14 ft; rear spacing 14–30 ft) and design tandem (25 + 25 kips at 4 ft), each with the 0.64 klf design lane load (AASHTO LRFD 3.6.1.2.2–3.6.1.2.4), truck and tandem taken separately (envelope). IM applies to the truck/tandem only, not the lane load (3.6.2.1). The live load is multiplied by the distribution factor (moment DF for moments, shear DF for shears and reactions) and by m; m defaults to 1.0 because the approximate distribution factors of 4.6.2.2 already include multiple presence (3.6.1.1.2). The 90% two-truck case (3.6.1.3.1) is not sent to Civil NX yet (it needs Lane Supports); tick the box to see its effect in the check solver only. In Civil NX: moving load code AASHTO LRFD, line lane LANE1, vehicles HL-93TRK / HL-93TDM, cases LLM (moment DF) and LLV (shear DF).
SER-I uses 1.0 on all three. Combinations add the static cases to the live-load envelope: max = DC + DW + LLmax, min = DC + DW + LLmin (no minimum DC/DW factors).

Material

User-defined (default) sends E, ν and γ directly, so it doesn't depend on Civil NX's database names (density γ = the Loads card value; mass = γ/g). E doesn't affect the moments when there's one material. Defaults: steel E 29,000 ksi, ν 0.30; concrete E = 57,000√4000 psi = 3,605 ksi, ν 0.20. "Civil NX database" needs the exact standard and grade names: "ASTM(S)" is a Civil NX steel standard but "A709-50" is a guess; enter the material once by hand and GET /db/MATL to see the exact names. Switching the type also switches γ to 0.490 (steel) or 0.150 (concrete) kcf.
